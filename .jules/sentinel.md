## 2024-05-15 - Exposed Sensitive Data in Console Logs
**Vulnerability:** The logger in `src/logger.js` was passing websocket event payloads directly to `window.console` without any sanitization. This could leak sensitive data (such as passwords, auth tokens, API keys) into the browser console, which might be read by malicious scripts or seen by users.
**Learning:** Websocket payloads are highly dynamic and can contain deeply nested objects, including cyclic references. A recursive deep-cleaning function mapping over both Objects and Arrays, using `WeakSet` to prevent infinite loops from circular references, is required. It's also important to explicitly check for plain objects using `Object.prototype.toString.call` to avoid accidentally destroying or failing to iterate over arrays, Dates, RegExps or Errors.
**Prevention:** Never pass raw data payloads from external sources (like websocket events or API responses) directly to logging mechanisms without implementing a sanitizer or filter that explicitly strips out well-known sensitive keys based on patterns (e.g., `password`, `token`, `secret`).
