## 2024-05-15 - Unsanitized Debug Log Exposure Risk
**Vulnerability:** The internal debug logger (`src/logger.js`) was configured to output raw JavaScript objects directly to `window.console` during WebSocket events and errors when `debug` mode was enabled. Because Socket.io payloads often include authentication tokens, session IDs, or sensitive user data, these could be inadvertently leaked to the browser's console, which is accessible by malicious browser extensions or XSS.
**Learning:** Even internal logging mechanisms intended only for debugging must sanitize inputs defensively. Relying on users not to enable `debug` mode in production or assuming socket payloads are safe to print creates a systemic vulnerability.
**Prevention:** Implement a robust serialization/sanitization layer (`sanitize`) within the logger to proactively redact common sensitive keys (`password`, `token`, `secret`, `credential`, `key`, `auth`) before any data reaches the console. Handled safely to avoid infinite loops on circular references.
