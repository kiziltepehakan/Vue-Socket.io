## 2024-05-15 - Prevent Sensitive Data Exposure in Client-Side Logs
**Vulnerability:** The client-side logger was logging incoming socket events and payloads directly to the browser console without sanitization. This meant any sensitive data (tokens, passwords, keys) sent via WebSockets could be inadvertently stored in user's console logs, potentially being captured by third-party scripts or exposed if the user shares their console output.
**Learning:** Client-side libraries that wrap WebSockets or data streams should inherently sanitize the payloads they log, as they cannot control the contents of the payload being sent by the application. Using a recursive object sanitizer with circular reference protection is necessary to safely clean these logs without destroying the observability of non-sensitive data.
**Prevention:** Implement a standard sanitization function on all logger inputs that scrubs keys matching common sensitive terms (password, token, secret, credential, key, auth). Ensure the sanitizer handles arrays, circular references, and ignores special objects like Errors or Dates.
