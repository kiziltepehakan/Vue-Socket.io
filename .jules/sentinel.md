
## 2024-05-30 - Exposed sensitive data in logs
**Vulnerability:** The logger class (`src/logger.js`) previously logged all socket and vuex event payloads indiscriminately to the browser console when debug mode was enabled. Because WebSockets often handle authentication tokens, passwords, and sensitive user data, these payloads would be fully exposed to the console, making them accessible to XSS attacks, browser extensions, or physical shoulder surfing.
**Learning:** Middleware libraries that act as conduits for application state (like Vuex/Socket.io integrations) must be extremely careful about what they log. Even if logging is "debug only," applications often leave debug mode enabled in production or beta environments by mistake. We cannot trust that the payloads flowing through our integration are safe to print. Circular reference handling is also critical when stringifying or traversing complex application state objects.
**Prevention:** Always implement a sanitization layer on top of `window.console` (or `console` in node) when building generic libraries that handle unknown user payloads. Use regex-based key matching (`/password|token|secret/i`) to redact values, and ensure safe traversal (ignoring non-plain objects, handling circular references via `Set`) to prevent observability tools from crashing the application.
