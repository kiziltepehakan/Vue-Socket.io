## 2026-07-24 - Information Exposure in Console Logs
**Vulnerability:** The `VueSocketIOLogger` in `src/logger.js` logged all events and associated data payload to the `window.console` directly when debug mode was enabled. This could lead to sensitive user data, such as passwords, tokens, or other credentials passed via WebSockets, being inadvertently logged to the browser console.
**Learning:** Browser console logs can be persisted, viewed by users (sometimes maliciously requested via social engineering), or intercepted by extensions. A global "debug" flag that blindly prints entire objects is a significant data leak vector. Deep objects and arrays also need sanitation, requiring protection against circular references to avoid crashing the logging mechanism.
**Prevention:** Implement a recursive data sanitization function (like the added `sanitize` method) before passing any object payload to the logging APIs. This method should filter known sensitive keys (e.g., matching `/password|token|secret|credential|key|auth/i`), correctly handle circular references (e.g., using a `WeakSet`), and be careful to avoid destroying standard observability features or failing on binary data.
