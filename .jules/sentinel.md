## 2024-05-14 - Sensitive Data Exposure in Logs
**Vulnerability:** The `VueSocketIOLogger` class logged all arguments passed to it directly to the console (`window.console`) without any sanitization. This meant that if a developer inadvertently passed a user object, authentication payload, or any other data structure containing sensitive fields (like passwords, tokens, API keys) into a logger method (info, error, warn, event), that sensitive data would be exposed in the browser's console in plaintext.
**Learning:** Even internal logging wrappers intended for development or debugging (`debug = true`) must treat the arguments they receive as potentially sensitive, especially when dealing with broadly scoped data like Vuex mutations or Socket.io events which can contain user credentials or session tokens. Exposing this information in the client-side console violates security best practices regarding data confidentiality.
**Prevention:** Always implement a `sanitize` or `redact` method on logger wrappers that recursively checks and masks sensitive keys (e.g., using a regex pattern like `/password|token|secret|credential|key|auth/i`) before passing the data to the underlying logging mechanism (`console.log`, `console.info`, etc.). Handle circular references to avoid infinite loops and explicitly handle primitive data types and standard objects (like `Error`, `Date`, `RegExp`).
