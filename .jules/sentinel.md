## 2024-10-31 - [Sensitive Data Exposure in Logs]
**Vulnerability:** The logger class `src/logger.js` previously logged all arguments passed to `info`, `error`, `warn`, and `event` directly to `window.console` without sanitizing them. This could lead to exposing sensitive user information like passwords, tokens, or other credentials in the browser console.
**Learning:** Even when logging is controlled by a `debug` flag, sensitive information should never be exposed in plaintext in browser devtools or standard outputs. Custom logger implementations need built-in sanitization to recursively redact sensitive keys from objects and arrays, being careful to handle circular references.
**Prevention:** Always implement a sanitization step before outputting data to logs. Ensure this sanitization handles plain objects and arrays recursively, redacts common sensitive keys (e.g., matching `/password|token|secret/i`), uses mechanisms like `WeakSet` to prevent infinite loops on circular structures, and avoids mutating or destroying the original data objects or specific types like `Error` or `Date`.
