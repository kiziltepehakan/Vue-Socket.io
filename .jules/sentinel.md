## 2024-05-23 - Prevent Sensitive Data Leakage in Logs
**Vulnerability:** The logger in `src/logger.js` indiscriminately logged event payloads directly into the browser console using `window.console.info`, `warn`, `error` methods. This could expose sensitive information, such as authentication tokens, user passwords, API keys, or application secrets, if they are inadvertently sent in socket events.
**Learning:** Even client-side loggers need sanitization. Just because a console is "local" to the browser doesn't mean sensitive variables should be dumped. Browser extensions, local malware, or shoulder-surfing could exploit this data, or the user may unwittingly export logs containing secrets.
**Prevention:** Implement a recursive sanitization mechanism on all logged objects to redact keys matching sensitive keywords (e.g. password, token, secret, auth). Ensure the sanitizer handles circular references to prevent stack overflow errors, and properly preserves native objects like `Error` and `Date`.
