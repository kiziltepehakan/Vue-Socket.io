## 2024-03-24 - [Information Disclosure] Fix sensitive data leakage in debug logs
**Vulnerability:** The logger class was directly passing objects and data straight into `console.info`, `console.warn`, and `console.error` without sanitizing them. This means that if a developer turns on debug logging, they could inadvertently log sensitive user data (like passwords, tokens, auth objects, etc.) that passed through socket events or vuex actions/mutations to the console, and ultimately to external monitoring systems depending on the environment.
**Learning:** Even debug features or logging functionalities strictly intended for development can become a significant vector for information disclosure if they are inadvertently shipped, or if user's enable them in unintended environments. Any system logging dynamic data (especially those hooking into generic data streams like Vuex state or raw socket payloads) needs sanitization boundaries.
**Prevention:** Implement a sanitization step for all debugging and logging outputs. This mechanism should intercept and redact values for keys matching known sensitive patterns (e.g., `password`, `token`, `secret`) while safely handling complex objects like arrays and avoiding stack overflows from circular references.
