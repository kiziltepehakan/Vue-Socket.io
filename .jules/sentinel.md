## 2024-05-24 - Prevent Sensitive Data Leakage in Logs
**Vulnerability:** The logging functions `info`, `error`, `warn`, and `event` in `src/logger.js` printed raw object data to the console without sanitization. This posed a security risk where sensitive application state or payload data containing keys like "password", "token", "secret", "credential", or "auth" could be exposed in browser consoles or log aggregators if debug mode was enabled.
**Learning:** The existing codebase lacked a centralized mechanism to strip sensitive details before pushing them to `window.console` methods. Directly passing unstructured arguments to logging methods often results in unintentional disclosure.
**Prevention:** Implement a recursive data sanitization method (`sanitize` in `src/logger.js`) that safely parses Plain Objects and Arrays (avoiding prototypes, functions, Errors, Dates, RegExps, or cyclic references). The method scrubs properties matching common sensitive key naming conventions (`/password|token|secret|credential|key|auth/i`) by replacing their values with `'[REDACTED]'`. Ensure this sanitizer wraps all data points passed to log output.
