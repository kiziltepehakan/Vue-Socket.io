## 2024-05-15 - [Exposed Sensitive Data in Client Logs]
**Vulnerability:** Client-side websocket logger (VueSocketIOLogger) was logging full, unsanitized socket payload data to `window.console` when debug mode was enabled. This could lead to exposing authentication tokens, passwords, or other sensitive information sent over websockets directly into the browser's console, where malicious scripts or extensions might read it.
**Learning:** Even client-side loggers intended for "debug only" should defensively sanitize incoming payloads, as developers may inadvertently leave debug mode on in production, or sensitive data might leak during development/testing. Handling complex objects robustly (recursively checking plain objects/arrays while safely preserving standard types like Error/Date and short-circuiting circular references) is necessary so sanitization logic itself doesn't crash the application.
**Prevention:** Implement a recursive sanitization mechanism on client-side logger outputs that targets common sensitive keys using a Regex before printing complex data structures to the browser console. Use `WeakSet` to prevent infinite loops from circular references.
