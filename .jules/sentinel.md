## 2024-06-21 - [Fix sensitive data exposure in logs]
**Vulnerability:** The logging class `VueSocketIOLogger` was passing raw, unsanitized socket objects directly to `window.console.info/warn/error`. If any part of the socket payload contained sensitive information (e.g. auth tokens, passwords, keys), it would be leaked to the browser console.
**Learning:** This codebase acts as an interface between Socket.IO and Vuex, meaning it naturally proxies potentially sensitive data payloads (like login attempts or token refreshes). Global logging utilities must proactively sanitize payloads they handle. Because of JS's reference semantics, simple stringification isn't always possible (due to circular JSON errors).
**Prevention:** Implemented a robust, recursive `sanitize` method on the logger class that intercepts all objects before logging. It checks against a regex of sensitive keywords (e.g., password, token, secret), safely handles circular structures using a `Set`, and strictly avoids processing complex class instances (like binary data) to prevent breaking observability.
