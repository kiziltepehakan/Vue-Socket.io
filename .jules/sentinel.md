## 2024-05-18 - Exposed Sensitive Data in Browser Console
**Vulnerability:** The internal `VueSocketIOLogger` class would log full payload and socket connection data directly to `window.console` when `debug` mode was enabled, which could inadvertently expose passwords, API keys, or authentication tokens sent via websockets to any user checking the developer tools.
**Learning:** Browser environments don't have separated log streams (like stdout vs separate files in Node.js). Everything sent to `console.log` in a browser plugin context is fully public. We must defensively sanitize logging mechanisms, not just network requests. Additionally, when implementing a log sanitizer on untyped runtime objects, we must explicitly track object references (`seen = new Set()`) to prevent the logger from freezing the main thread if it encounters an object with circular references (e.g. self-referencing Vue components or DOM nodes in the payload).
**Prevention:** Implement a `sanitize` method on the logger class that deep-clones/traverses plain objects and arrays to explicitly redact keys matching patterns like `/password|token|secret/i` before printing. It must handle circular references correctly. Ensure all logging proxy methods (like `info`, `warn`, `error`) process `arguments` through this sanitizer.
