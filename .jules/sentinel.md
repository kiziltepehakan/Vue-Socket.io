## 2024-10-24 - Sensitive Data Exposure in Logs
**Vulnerability:** The logger class (`src/logger.js`) was directly logging objects to the console in debug mode without sanitizing them. This could inadvertently expose sensitive user data (like passwords, tokens, or API keys) if they were present in the payload of socket events.
**Learning:** We need to be careful when sanitizing deeply nested objects that may have circular references or complex binary data (e.g., ArrayBuffer, File, Blob), as a naive traversal might freeze the browser. Using a `WeakSet` to track seen objects and checking for plain objects prevents circular reference infinite loops, and strict type checking prevents breaking on non-plain objects.
**Prevention:** Implement an object sanitizer that recursively redacts known sensitive keys (e.g., using a regex `/password|token|secret|credential|key|auth/i`) while ensuring it handles circular references gracefully and does not traverse complex/non-plain objects. Apply this to all generic logging methods.
