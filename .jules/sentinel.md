## 2026-05-02 - [Sensitive Data Exposure in Browser Logging]
**Vulnerability:** The `VueSocketIOLogger` was directly passing raw WebSocket event data and payload arguments to `window.console` (via `info`, `error`, `warn`, and `event` methods) when debug mode was enabled. Because Socket.io events often carry entire state objects or payloads containing authentication credentials, this inadvertently exposed sensitive properties like `password`, `token`, and `secret` in plain text within the browser's developer console, leaving them accessible to anyone with physical access or XSS capabilities.
**Learning:** Browser console logging of arbitrary application payloads presents a substantial risk of unintended data leakage, especially in communication layers like Socket.io integrations that typically handle sensitive authentication tokens or credentials directly from the server.
**Prevention:** Implement recursive, robust sanitization on all outgoing logger payloads before passing them to the console API. The sanitization must selectively replace keys matching sensitive patterns (e.g., `/password|token|secret/i`) with a `[REDACTED]` placeholder, while carefully handling plain objects and arrays to avoid unhandled circular references or destructive mutations to the original application state.
