## 2026-05-10 - Sensitive Data Exposure via Client-Side Logging
**Vulnerability:** The internal `Logger` printed raw socket event data directly to `window.console` when debug mode was enabled. This could expose sensitive payload data (e.g., authentication tokens, user passwords, credentials) in the user's browser console, posing a risk if screenshots or screen shares are taken, or if cross-site scripting (XSS) is present.
**Learning:** Even "debug" loggers in client-side libraries should sanitize their inputs if there is a possibility that arbitrary application state or payloads containing secrets might be routed through them.
**Prevention:** Implement recursive data sanitization in all logger implementations. Match on standard sensitive keys (`password`, `token`, `secret`, `credential`, `key`, `auth`) to redact sensitive strings before outputting them to native console methods. Explicitly manage circular references to prevent application lockup during sanitization.
