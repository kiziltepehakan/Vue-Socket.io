## 2024-07-18 - Exposed Sensitive Data in Socket.io Logs
**Vulnerability:** The internal `VueSocketIOLogger` class in `src/logger.js` logged all raw event data sent through `VueSocketIO` using `window.console` without sanitization. In real-world usage, socket events often transport sensitive data (like passwords, authentication tokens, or keys), and these would be logged in plain text in the browser's console, creating a significant data exposure risk if debug mode is on.
**Learning:** Even internal logging mechanisms must implement a redaction mechanism. When wrapping the client's logger or `window.console`, assume that incoming payloads contain arbitrary user data and sensitive keys. We had to implement a recursive `sanitize` function with a `WeakSet` to prevent memory leaks/freezing on circular references, and whitelist only plain objects and arrays to avoid breaking complex structures like `Date`, `Error`, `RegExp` or binary data streams.
**Prevention:** Implement automatic sanitization for all logging utilities at the library boundary. Avoid logging full payloads indiscriminately. Specifically, ensure any generic logging mechanism sanitizes fields matching `/password|token|secret|credential|key|auth/i` before printing them.
