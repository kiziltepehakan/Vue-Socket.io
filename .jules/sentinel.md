## 2023-10-25 - Prevent Sensitive Data Leakage in VueSocketIOLogger
**Vulnerability:** The logger class `VueSocketIOLogger` was outputting raw socket event data directly to the browser console. If debug mode was active, this could expose sensitive information such as passwords, authentication tokens, or keys to malicious actors with console access.
**Learning:** All logs going into the client console must be treated as public output. Unsanitized state/event logs from external systems (like Vuex or Socket.IO) are high-risk sources for accidental secret disclosure. Also learned that when deep-cloning or iterating to sanitize objects, circular references and complex object types (like Date, RegExp, Error) must be handled carefully to prevent `RangeError: Maximum call stack size exceeded` or losing useful debugging context.
**Prevention:** Always implement a sanitization layer on client-side loggers to redact known sensitive keys (e.g., using a regex like `/password|token|secret|credential|key|auth/i`) before passing data to `window.console`. Ensure circular references are managed with `WeakSet` and limit recursion to plain objects and arrays.
