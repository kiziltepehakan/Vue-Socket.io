## 2024-05-18 - [Fix sensitive data exposure in logs]
**Vulnerability:** The logger in `src/logger.js` previously output raw payloads and parameters for all Socket.io events and Vuex mutations. Since these could contain sensitive data such as passwords, tokens, or credentials, debugging mode enabled meant all this sensitive info would be exposed in the browser's console.
**Learning:** Even though logging happens in the browser's console, logging sensitive user data is a security risk (e.g. against XSS or users sharing screenshots of the console). When designing loggers, especially those dealing with broad event buses or store state, one must consider that payloads can contain auth tokens and passwords. Circular dependencies also need handling to prevent recursion errors when traversing complex state objects.
**Prevention:** Implement a recursive sanitization mechanism on log payloads before sending them to the console. The sanitizer should redact specific known sensitive keys (e.g., `password`, `token`, `secret`, `credential`, `key`, `auth`) using regex, use `WeakSet` to prevent infinite loops from circular references, and carefully avoid breaking standard objects like `Error`, `Date`, or `RegExp` by selectively cloning plain objects and arrays only.
