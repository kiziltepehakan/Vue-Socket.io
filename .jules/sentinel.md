## 2026-03-26 - Sensitive Data Leakage in Logs
**Vulnerability:** The central `VueSocketIOLogger` was blindly logging all raw arguments and payloads from socket events directly to `window.console`. This risks exposing sensitive information (e.g., passwords, authentication tokens, or other credentials) inherently transmitted via websockets or Vuex store events if the application was inadvertently left in debug mode or if console outputs were ingested elsewhere.
**Learning:** Broad "catch-all" logging functions within integration middleware components easily become a conduit for sensitive data spillage. The lack of filtering allowed any attached socket listener's sensitive data to be visible in the user's browser console. Logging should be built defensively to redact PII and secrets prior to reaching the console sink.
**Prevention:** Implement recursive sanitization mechanisms inside generic loggers. The new `sanitize` function redacts keys indicating sensitive data (`password`, `token`, `secret`, `credential`, `key`, `auth`) while gracefully handling tricky data structures like circular references, binaries, and `Date` objects to avoid crashes or observability degradation.
