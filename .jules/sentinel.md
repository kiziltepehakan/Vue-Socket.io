## 2024-05-18 - Prevent Sensitive Data Leakage in Logger
**Vulnerability:** The `VueSocketIOLogger` class was passing unsanitized event data and store mutation payloads directly to `window.console` (when `debug` was enabled), potentially leaking passwords, tokens, and other credentials into browser console logs and possibly telemetry systems attached to it.
**Learning:** Security risks often emerge in "shitty logger" utility classes. It's crucial to recursively sanitize nested objects, but equally important to maintain a strict boundary for what objects should be sanitized: only plain objects and arrays should be traversed. Standard classes, complex instances, or circular references can cause crashes, infinite loops, or loss of critical debugging context if overly aggressive sanitation is applied.
**Prevention:** Implement deep sanitization for all logging utilities that may process arbitrary application state or network payloads. Utilize regex matching for common sensitive keys (`/password|token|secret|credential|key|auth/i`), use `Set` to track visited objects to prevent circular reference stack overflows, and ensure only plain `Object` or `Array` instances are deeply traversed to avoid mutating or destroying non-serializable objects (e.g., Dates, Errors, RegExps, File instances).
