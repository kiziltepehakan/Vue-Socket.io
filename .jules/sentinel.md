## 2024-05-15 - Data Leakage via Unsanitized Application Logs
**Vulnerability:** The `VueSocketIOLogger` class logged the raw `data` argument passed to `info`, `event`, `error`, and `warn` methods directly using `window.console`. This data often included sensitive user state, tokens, passwords, or authentication payloads sent across WebSocket channels.
**Learning:** Application-level debug loggers, especially those that hook into global state managers or network events, can easily become vectors for data exposure. In browser environments, logging sensitive data to the developer console makes it trivially accessible to malicious browser extensions or XSS attacks. Attempting to deep copy or stringify data for sanitization can fail due to circular references or non-plain objects, breaking the application.
**Prevention:** Implement recursive object traversal with circular reference detection (using a `Set`) explicitly designed to mutate a safe copy. Target common sensitive keys (e.g., `password`, `token`, `secret`, `credential`, `key`, `auth`) using a regular expression and replace their values with `[REDACTED]`. Return early for non-plain objects, `Error`, `Date`, and `RegExp` types to preserve observability and prevent runtime freezing. Apply this sanitization to all log level outputs.
