
## 2024-05-18 - Prevent sensitive data leakage in logger
**Vulnerability:** The logger (`VueSocketIOLogger`) in `src/logger.js` printed raw payload data directly to the browser console when `debug` mode was true. This could leak sensitive information like passwords, secrets, or API keys directly into logs if they were transmitted over sockets or handled in vuex store events (CWE-532).
**Learning:** Never assume debug mode is only used with safe data. Internal framework loggers that intercept wide ranges of application events (like all socket payloads or vuex mutations) must implement active sanitization mechanisms because they don't control the data passing through them. It's critical to redact sensitive keys and safely handle complex objects (e.g., circular references, class instances) so the logger doesn't crash the application while trying to secure it.
**Prevention:** Implement a recursive data sanitization method (`sanitize`) that replaces values of sensitive keys (matching `/password|token|secret|credential|key|auth/i`) with `[REDACTED]`. Use `WeakSet` to prevent infinite recursion on circular objects and ensure non-plain objects (like Maps/Sets/binary data) are passed through without getting destroyed.
