## 2024-06-25 - Prevent Sensitive Data Leak in VueSocketIOLogger
**Vulnerability:** The `src/logger.js` exposed a method that logged incoming events and associated parameters to the `window.console` when debug was enabled. This could lead to exposing sensitive information (e.g., passwords, auth tokens, API keys) in the browser console.
**Learning:** Raw event parameters shouldn't be logged directly without considering what data could be in them. Even if `debug` is normally off in production, a client-side setting could turn it on and leak secrets. The logger also needed to avoid crashing on circular references.
**Prevention:** Implemented a robust `sanitize` method on the logger class. It intercepts event payloads and argument values, traverses the object/array structure safely (avoiding circular references via `WeakSet`), and replaces values associated with common sensitive keys (`password`, `token`, `secret`, `credential`, `key`, `auth`) with `[REDACTED]`. It uses a focused check on plain objects and arrays to ensure things like binary strings, dates, and typical class structures (like Vue/Socket internals) aren't mistakenly destroyed during sanitization.
