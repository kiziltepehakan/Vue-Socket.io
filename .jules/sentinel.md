## 2026-07-23 - Sensitive Data Exposure in Logs
**Vulnerability:** The logger in `src/logger.js` was indiscriminately logging all provided data directly to the console (`window.console.info`, etc.). If components or store modules passed objects containing sensitive fields (like tokens or passwords) to Socket.io events, these would be exposed in the browser console.
**Learning:** This highlights the risk of relying on uncontrolled client-side logging when dealing with global state (Vuex) or real-time event systems (Socket.io) where payloads often contain mixed authentication or user data. Even in "debug" mode, sensitive fields should be redacted to prevent accidental exposure during debugging or in production builds if `debug` is left on.
**Prevention:** Always implement a sanitation layer in any custom logging utility that recursively traverses payload objects and arrays. Redact known sensitive keys using regex matching (e.g., `/password|token|secret|credential|key|auth/i`) while safely handling circular references and skipping binary data structures.
