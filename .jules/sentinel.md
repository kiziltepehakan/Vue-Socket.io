## 2024-05-24 - Information Exposure in Debug Logger
**Vulnerability:** The debug logger printed any objects directly to the browser console, potentially exposing sensitive information such as passwords, tokens, or credentials that are being transmitted over WebSocket connections.
**Learning:** Even internal or debug tools can leak sensitive data if user data (events or payloads) is not sanitized. WebSocket event payloads frequently contain sensitive auth payloads. The solution needs to carefully process complex JS objects (avoiding breaking on circular structures or specific object types) without destroying the observability of normal non-sensitive data.
**Prevention:** Implement sanitization functions on all data sent to output logs (like `console.info`) that replace known sensitive keys with `[REDACTED]`. Use defensive recursive sanitization techniques (e.g. `WeakSet` for circular dependencies, `Object.getPrototypeOf(data) === Object.prototype` to identify plain objects) to avoid unintended crashes.
