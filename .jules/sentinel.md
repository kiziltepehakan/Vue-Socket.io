## 2024-05-24 - Unsanitized Debug Logging Leaking Sensitive Data
**Vulnerability:** The `VueSocketIOLogger` class logged raw arguments directly to `window.console` when debug mode was enabled. Because Socket.io events and Vuex data often contain authentication tokens, credentials, or sensitive user data, these would be directly logged and exposed in the browser's developer console.
**Learning:** Even internal logging mechanisms must implement defensive sanitization. Third-party or application-level events mapped directly to store actions/mutations often carry authentication payloads that should not traverse through simple observability tools without inspection.
**Prevention:** Implement recursive sanitization functions on the entry point of the logger that mask keys matching a regex (e.g., `/password|token|secret|credential|key|auth/i`). When designing loggers, always intercept arguments and strip PII/secrets before sending to the native console, specifically handling cyclic object references to avoid crashes.
