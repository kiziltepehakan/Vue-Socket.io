## 2024-05-18 - Client-Side Logging Sensitive Data Exposure
**Vulnerability:** The logger in `src/logger.js` previously forwarded arbitrary socket events directly to `window.console` without sanitization. While logging was disabled by default, any user enabling debug mode could unwittingly log highly sensitive data (e.g., auth tokens, passwords, keys) to the browser console, risking exposure.
**Learning:** Browser console output is highly visible. Client-side libraries forwarding generic application payloads must proactively strip sensitive information, as they cannot control what consumers broadcast. Proper sanitization handles infinite recursion (circular references) and leaves complex native objects (like Maps/DOM nodes) intact to preserve usability while explicitly catching plain POJOs containing secrets.
**Prevention:** Implement recursive sanitization targeting specific regex-matched keys for credentials whenever emitting unknown data shapes into telemetry or standard output/console streams, wrapping object cloning logic with WeakSet recursion prevention.
