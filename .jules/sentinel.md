## 2026-09-01 - Prevent Sensitive Data Leakage in Application Logs
**Vulnerability:** The custom logger (`src/logger.js`) was outputting raw un-sanitized objects to `window.console`. If an application sent sensitive objects (like payloads containing passwords, authentication tokens, API keys) via Vuex or directly emitted socket events, they would be visible in browser console logs.
**Learning:** In frontend libraries bridging data flows (like socket.io to Vuex), observability tools must assume they are passing through highly sensitive state. Direct pass-throughs into the console pose a risk of exposing user secrets. Furthermore, a sanitizer for logging must cleanly handle non-serializable constructs (circular objects) and domain-specific object types (`Error`, `Date`, `RegExp`) to avoid freezing the tab or destroying debugging utility.
**Prevention:** Implement a recursive data sanitizer across all logger ingress points that aggressively scrubs common sensitive keys (`password`, `token`, `secret`, `credential`, `key`, `auth`) while using `WeakSet` tracking for circular structures.
