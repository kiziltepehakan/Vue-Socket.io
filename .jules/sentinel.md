## 2024-05-15 - Prevent Sensitive Data Exposure in Logs
**Vulnerability:** The logger (`src/logger.js`) in vue-socket.io-v4 logged raw event payloads and application state objects without any redaction. This allowed sensitive data (like passwords, auth tokens, secrets) present in Vuex state or socket event payloads to be inadvertently logged to the browser console when `debug` mode was enabled, exposing them to anyone with access to the console or log aggregation tools.
**Learning:** Logging entire state objects or unvetted socket payloads is inherently dangerous. Standard logging mechanisms should intercept and sanitize objects to ensure credentials and tokens do not slip through into telemetry or local consoles. Circular references and specific JS objects (Error, Date, RegExp) must be handled carefully when traversing objects for sanitization.
**Prevention:** Implement an object-traversal sanitization method in the central logger. This method should use a regex (e.g., `/password|token|secret|credential|key|auth/i`) on object keys and replace matching values with `[REDACTED]`. It must be applied to all arguments in all logging functions (`info`, `error`, `warn`, `event`).
