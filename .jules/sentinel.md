## 2024-04-22 - Prevented Sensitive Data Leakage in Websocket Payloads
**Vulnerability:** The logger in `src/logger.js` was dumping full websocket payload data (from `info`, `error`, `warn`, and `event` methods) directly to `window.console` when debug mode was enabled. This could expose credentials, authentication tokens, and API keys to the browser console.
**Learning:** Even though `debug` might be disabled in production, any environment running with debug mode would invisibly leak potentially sensitive auth keys from the Vuex store or websockets into the browser console if it simply logs the full arguments array. Furthermore, when writing custom JSON serialization or sanitization, recursive handling of plain objects with `WeakSet` (or `Set`) is necessary to avoid "Maximum call stack size exceeded" errors with circular references.
**Prevention:** Implement a recursive sanitization hook before sending telemetry/debug information to the console. The hook should mask keys matching sensitive regex patterns (e.g., `/password|token|secret/i`) with `[REDACTED]`.
