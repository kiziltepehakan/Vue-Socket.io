## 2026-10-05 - Sensitive Data Exposure in Logs
**Vulnerability:** The logger class (`src/logger.js`) logged all Vuex and socket event payloads directly to the browser console without any sanitization. This caused sensitive user data (like passwords, tokens, auth objects) transmitted via WebSocket events to be exposed to anyone who could view the browser's developer console or if another script collected console logs.
**Learning:** Browser environments lack strict visibility control for `console` outputs. When a library automatically bridges network data (WebSocket) and state management (Vuex) while eagerly logging payloads for debugging purposes, it becomes a direct pipeline for sensitive data leakage if logging is ever turned on in production or observed by malicious actors locally.
**Prevention:** Implement recursive sanitization functions that target common sensitive key patterns (`/password|token|secret|credential|key|auth/i`) within plain objects and arrays before passing them to logging interfaces. Handle circular references safely using `WeakSet` to avoid infinite loops, and avoid mutating original objects.
