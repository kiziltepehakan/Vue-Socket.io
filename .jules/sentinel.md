## 2024-03-12 - Sensitive Data Leakage in Browser Logs
**Vulnerability:** The `VueSocketIOLogger` was directly passing incoming socket data to `window.console` without any sanitization. If the application handles sensitive events (like authentication packets with passwords or tokens), these would be exposed in plaintext within the browser developer tools, presenting a risk if screen sharing or log exporting occurs.
**Learning:** Browser devtools represent a trust boundary, and we must treat them similarly to external server logs. Raw incoming packets from libraries like `socket.io-client` can carry sensitive arguments that we should not indiscriminately broadcast to `console`. Additionally, when performing sanitization, we need robust checks like `WeakSet` to prevent infinite loops when handling complex, circularly-referenced Vuex states or objects.
**Prevention:** Implement a recursive sanitization mechanism that redacts object keys matching common patterns (`password`, `token`, `secret`, `credential`, `key`, `auth`) before any data hits the `console` APIs. Apply this check generally across all logging methods (`info`, `error`, `warn`, `event`).
