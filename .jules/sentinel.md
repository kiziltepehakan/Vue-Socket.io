## 2026-04-08 - Prevent Sensitive Data Leakage in Client-side Logger
**Vulnerability:** The `VueSocketIOLogger` class in `src/logger.js` passed all event payloads directly to `window.console.info`, `.warn`, and `.error`. Since this library is used to handle real-time WebSockets communication, payloads could easily contain sensitive information such as authentication tokens, passwords, or PII. If an application inadvertently ships with `debug: true` or a user manages to observe the console in production/staging environments, this sensitive data would be logged directly to the browser console.
**Learning:** Client-side libraries that act as middleware or event wrappers (like Socket.io integrations) must proactively implement defense-in-depth measures against accidental data exposure. We cannot blindly trust that developers will sanitize payloads before broadcasting them.
**Prevention:** Implement an automatic, safe, recursive `sanitize` method on the logger class that filters out common sensitive keys (e.g., password, token, secret, credential, key, auth) before passing data to `window.console`. Handle circular references safely using `WeakSet` (or `Set` for broad compatibility) to ensure the logger itself does not cause infinite loops or crash the application.
