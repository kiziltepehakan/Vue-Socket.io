## 2024-06-23 - [Prevent Sensitive Data Exposure in Logger]
**Vulnerability:** The `VueSocketIOLogger` in `src/logger.js` logged all events and data verbatim. This could lead to sensitive information (like passwords, auth tokens, etc.) sent via WebSockets being output into the browser's console, which is often ingested by error monitoring tools (e.g., Sentry, LogRocket).
**Learning:** Security by default means all debugging and logging components must treat dynamic runtime data as untrusted/sensitive by default and sanitize it before it reaches any sinks, especially in a widely distributed client-side library. Careful handling of deep-copying/sanitization is required to prevent breaking cyclic object structures (using WeakSet) or mangling complex object types.
**Prevention:** Implement proactive sanitization for standard security-sensitive field names (password, token, secret, auth, key) in the base logging utility of any library interacting with potentially sensitive payloads. Ensure sanitizers robustly handle edge cases like circular references and non-plain objects to prevent unexpected crashes.
