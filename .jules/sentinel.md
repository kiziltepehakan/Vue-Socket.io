## 2026-03-20 - [CRITICAL] Fix sensitive data exposure in logs
**Vulnerability:** The `VueSocketIOLogger` was directly passing raw data objects to `window.console` methods without redaction. Given that this is a Socket.io wrapper handling payloads (which can contain authentication tokens, passwords, API keys, etc.), these credentials could easily leak into the browser developer console.
**Learning:** Redacting data in a generic logger must handle arbitrary structures. Doing a deep clone and replace is risky for potentially large or deeply nested frontend objects and can cause crashes due to circular references or freezing on un-stringifiable/complex structures (e.g. DOM elements, binary data). It's crucial to employ an explicit safe-serialization function that uses a `Set` to track visited nodes and strictly processes only plain objects (`[object Object]`) and arrays, returning primitives unchanged.
**Prevention:** Implement recursive sanitation layers specifically targeting known credential keys with `/password|token|secret|credential|key|auth/i`, and incorporate `seen` sets to gracefully mitigate callstack overflow loops on circular reference data before outputting to any logging or monitoring tool.
