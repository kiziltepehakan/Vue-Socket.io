## 2024-05-18 - Prevent Console Log Leakage of WebSocket Payloads
**Vulnerability:** The logger class was blindly printing raw data to `window.console` (`console.info`, `console.error`, `console.warn`) for incoming and outgoing WebSocket events if debug mode was enabled. This risks exposing sensitive information such as tokens, passwords, and secrets that are transmitted as part of WebSocket payloads, especially because debugging is often accidentally left enabled or toggled on dynamically in production environments.
**Learning:** Browser environments serialize complex objects when logged. When intercepting and logging raw protocol data (like WebSocket payloads), a naive passthrough to `console` exposes all keys. Attempting to traverse and sanitize the data structure must correctly handle circular references and avoid clobbering objects with prototypes to prevent freezing/crashing the client.
**Prevention:** Implement a recursive data sanitization mechanism for all logging functions that checks for common sensitive keys (`password`, `token`, `secret`, `credential`, `key`, `auth`) and safely sanitizes them, replacing values with `[REDACTED]`. The sanitizer should gracefully handle circular references via `WeakSet` and strictly evaluate plain objects or arrays.
