## 2026-09-03 - Exposing Sensitive Data in Logs
**Vulnerability:** The logger (`src/logger.js`) forwarded raw event data, objects, and configurations directly to `window.console` methods without any filtering. This would expose any sensitive data (like passwords, auth tokens, secrets) present in Socket.io payloads or store actions/mutations to the client's browser console, which poses a serious information leakage risk.
**Learning:** Even internal logging mechanisms, especially in browser-facing libraries, need defensive data masking to prevent accidental exposure of user or authentication data that might be bundled into general-purpose payloads. Handling circular references safely while retaining standard log formats (like JS errors/dates) is critical for logger decorators.
**Prevention:** Always implement a sanitization layer for browser console logging wrappers that recursively traverses and redacts specific sensitive keys (e.g., password, token, secret) from payloads before logging.
