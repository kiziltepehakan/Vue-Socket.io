## 2024-03-11 - Sensitive Data Exposure in Debug Logs
**Vulnerability:** The logger class (`src/logger.js`) dumped raw data objects to `console.info`, `console.warn`, etc., when debug mode was enabled. This could lead to sensitive information (passwords, tokens, API keys) from Socket.io events or internal state being exposed in the browser console.
**Learning:** Developers often rely on libraries to handle logging transparently, potentially overlooking what actual data is passed through. A generic logger that blindly passes through uninspected objects poses a risk, particularly in front-end applications where console output can easily be seen by users or captured by external tools/extensions.
**Prevention:** Implement recursive sanitization for all objects before passing them to the console. Look for common sensitive keys (`password`, `token`, `secret`, `credential`, `key`, `auth`) and replace their values with `[REDACTED]`. Use `WeakSet` to handle circular references safely to prevent maximum call stack errors during traversal.
