## 2024-05-14 - Prevent sensitive data exposure in client-side logs
**Vulnerability:** The logger class `VueSocketIOLogger` was logging potentially sensitive data (like Vuex state, component data, socket payloads) directly to the browser console without any sanitization. Any object passed to `info`, `error`, `warn`, or `event` was logged as-is.
**Learning:** Client-side libraries often handle application state which may contain sensitive user information (tokens, passwords, PII). Logging this raw data to the console can expose it to malicious extensions or cross-site scripting (XSS) attacks that access the console or capture the screen.
**Prevention:** Implement a recursive sanitization function that redacts sensitive keys (e.g., using a regex like `/password|token|secret|credential|key|auth/i`) before logging. The sanitization must handle circular references to avoid infinite loops and should only process plain objects/arrays to preserve special objects like `Error` or `Date`.
