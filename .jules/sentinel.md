## 2024-05-01 - Sensitive Data Exposure in Frontend Logger
**Vulnerability:** The `VueSocketIOLogger` was directly passing unredacted application state and payloads to `window.console` methods when debug mode was enabled. This could expose sensitive information like passwords, tokens, or API keys in the user's browser console, posing a high security risk if the user screen-shares, submits a bug report with console logs, or if malicious scripts access the console output.
**Learning:** Even though logging is typically disabled in production, any custom logger must assume that sensitive data will eventually be passed to it. Relying on "debug mode" being off is insufficient defense. Additionally, deeply nested objects and arrays require recursive sanitization, and we must carefully handle circular references to avoid infinite loops when serializing complex state objects.
**Prevention:** Implement a recursive data sanitization function in all custom loggers that automatically redacts common sensitive keys (e.g., matching `/password|token|secret|credential|key|auth/i`) before passing the data to the native console. Use a `WeakSet` to safely handle circular references without destroying observability.
