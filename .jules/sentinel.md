## 2023-10-24 - [Data Leakage] Fix sensitive data exposure in console logs
**Vulnerability:** Client-side logger `src/logger.js` exposed raw Socket.io payloads and Vuex events directly to `window.console` when debug mode was enabled. This could log plain text sensitive data like passwords, tokens, or API keys directly to the browser console.
**Learning:** Centralized debug logging utilities must defensively sanitize payloads before handing them to the console, even if the feature is intended strictly for development or debugging (as it might inadvertently be enabled in other environments or during active sessions).
**Prevention:** Implement recursive sanitization functions that target common sensitive key names (`password`, `token`, `secret`, `credential`, `key`, `auth`) on incoming payloads. Furthermore, use defensive traversing techniques (e.g. tracking seen object references) to prevent `Maximum call stack size exceeded` errors due to circular references in complex Vuex or DOM-bound objects.
