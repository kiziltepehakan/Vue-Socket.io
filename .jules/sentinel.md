## 2024-06-19 - Sensitive Data Exposure in Websocket Logs
**Vulnerability:** The `VueSocketIOLogger` class indiscriminately logged all incoming websocket events and payload data to the browser console when `debug` mode was enabled. This could lead to exposing sensitive user information (like tokens, passwords, credentials) stored in event payloads.
**Learning:** Even in "debug" modes intended for development, broad logging mechanisms can easily slip into production configurations or be toggled by users, leaking sensitive data to the client-side browser console which could be accessed by malicious scripts or physical shoulder surfing. A robust sanitization pattern is required to intercept and clean payloads before passing them to the console API. The sanitization must handle deep nested objects, arrays, circular references, and avoid mutating original objects or throwing on unexpected types.
**Prevention:** Implement recursive input sanitization for all logging utilities. The `sanitize` function built for this project uses a `Set` to track visited objects (preventing infinite loops from circular references), gracefully ignores non-plain objects like `Error` or `Date`, and uses regular expressions to redact keys matching patterns like `/password|token|secret|credential|key|auth/i` before passing the data to `window.console`.
