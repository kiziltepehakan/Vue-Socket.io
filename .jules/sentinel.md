## 2026-04-24 - [Cleartext Logging Fix]
**Vulnerability:** Cleartext Storage of Sensitive Information (CWE-312) / Exposure of Sensitive Information in Debug Logs. The `VueSocketIOLogger` was logging raw WebSocket payloads directly to the browser console when debug mode was enabled. Because WebSockets often handle authentication tokens and secure payloads, these could easily leak out to any third-party scripts parsing console logs or via shoulder-surfing.
**Learning:** In event-driven WebSocket architectures, payloads are highly unpredictable and commonly deeply nested or contain complex objects with circular references. A simple JSON stringify/regex approach would freeze the UI or strip useful telemetry. A recursive payload sanitation mechanism mapping over Plain Objects and Arrays while tracking circular references via a `Set` allows for high performance without crashing the browser, and avoids freezing native objects like DOM elements, Errors, or Dates.
**Prevention:** Implement recursive redaction logic for complex data-structures on the logger-side that respects application memory constraints and native objects. Any module implementing debug console logs should default-off, and actively filter objects containing patterns like `/password|token|secret|credential|key|auth/i` before touching stdout/console.
