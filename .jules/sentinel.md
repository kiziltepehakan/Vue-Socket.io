## 2024-05-18 - [Exposed Sensitive Data in Logs]
**Vulnerability:** The logger in `src/logger.js` passed application data (such as login payloads or events) directly to `window.console` without any redaction. This could potentially expose sensitive user data (passwords, auth tokens) into browser developer tools or log aggregators connected to console output.
**Learning:** Even simple, client-side browser loggers need sanitization if they are designed to log generic websocket event payloads and dispatch actions, because the user could inadvertently pass sensitive login objects through the event payload. The implementation required handling circular references using a `WeakSet` to prevent freezing or crashing when the user supplied objects with recursive structures. It also needed to limit processing to plain objects and arrays to prevent issues with complex objects like Date, Regex or binary streams.
**Prevention:** Always implement an automatic redaction mechanism for any generic logging layer that deals with unrestricted event payloads or user data structures.
