## 2025-01-28 - Client-Side Logger Data Leakage
**Vulnerability:** The client-side logger (`VueSocketIOLogger`) was directly logging complete objects/arguments to `window.console` without any sanitization. This means if sensitive user data, authentication tokens, or credentials were included in socket events, they would be visible in the user's browser console, posing a significant security risk for data exposure.
**Learning:** Client-side libraries that abstract underlying network connections (like Socket.IO) often act as a conduit for sensitive data. Developers might unwittingly log whole message payloads for debugging purposes, not realizing that these logs persist in the browser's developer tools and can be accessed by malicious scripts or physical shoulder surfing. A simple boolean `this.debug` flag is insufficient protection because it might be enabled in pre-production environments or inadvertently turned on in production.
**Prevention:** Always implement data sanitization at the logging boundary. Before any object or array is passed to a console function, it should be recursively traversed to redact known sensitive keys (e.g., matching regex `/password|token|secret|credential|key|auth/i`). It's also crucial to safely handle circular references during traversal to prevent stack overflows and to preserve non-plain object types like `Error`, `Date`, and `RegExp` to maintain logging usefulness.
