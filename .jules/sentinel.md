## 2024-05-20 - Exposed Sensitive Data in Logs
**Vulnerability:** The Vue-Socket.io logger (`src/logger.js`) logged all received payload data directly to the browser console (`window.console`) without any sanitization. This meant any sensitive information (like passwords, tokens, API keys) sent over Socket.io could be exposed to anyone who opens the developer tools, potentially violating security and privacy standards.
**Learning:** Directly passing incoming payload objects to logging functions in a library designed for front-end usage poses a significant risk of data exposure. Even if logging is only active in "debug" mode, it's safer to redact known sensitive keys proactively. The previous implementation used `...arguments` which bypassed any processing.
**Prevention:** Always implement a sanitization or redaction layer before sending data to output streams (like `window.console` or external logging services). A recursive sanitization function that checks object keys against a regex of known sensitive terms (e.g., `/password|token|secret|credential|key|auth/i`) and replaces their values with a placeholder (e.g., `[REDACTED]`) provides a good defense. It's crucial to handle circular references (using `WeakSet`) and preserve native types (like `Error`, `Date`, `RegExp`) to avoid breaking the application or the usefulness of the logs.
