## 2024-05-30 - Prevent Sensitive Data Leakage in Debug Logs
**Vulnerability:** The `VueSocketIOLogger` in `src/logger.js` logged all events and data payload directly to the browser console without sanitization when `debug` was enabled. This could result in sensitive information (passwords, auth tokens, secret keys) being exposed in the browser's developer tools console, potentially leading to a local data leak if the user's screen is shared or observed, or if debug mode was inadvertently left enabled in production environments.
**Learning:** We need a way to sanitize plain objects or arrays when they contain keys referencing sensitive information such as 'password', 'token', 'secret', etc., to avoid data leakage while still making the log output informative. We also must handle circular references correctly when processing these object payloads.
**Prevention:** Implement a recursive data sanitation layer on inputs to log handlers. Use `Set` tracking to detect circular references during serialization and stop recursion, and apply an allow/deny list of regex-based keys to filter out PII or sensitive credentials before calling `console.*` methods. Ensure only plain objects and arrays are modified.
