## 2026-10-26 - Sensitive Data Exposure in Logs
**Vulnerability:** The logger class (`src/logger.js`) in vue-socket.io-v4 logged all provided payload data to the console without any form of sanitization. When socket events contain sensitive data (e.g. passwords, authentication tokens, secret keys) they would be leaked in clear text to the browser's console, risking exposure through browser extensions, screen sharing, or physical observation.
**Learning:** Client-side libraries designed to integrate and broadcast internal application events and state (like socket events to Vuex) must assume that some payloads will carry sensitive credentials. Blindly logging `...args` and un-sanitized payloads breaks the "fail securely" and "trust nothing" principles, resulting in immediate data exposure.
**Prevention:** Implement recursive logging sanitizers that explicitly filter or redact fields matching sensitive patterns (e.g. `/password|token|secret|credential|key|auth/i`). The sanitizer must be careful to handle circular references (via `WeakSet`) and only process plain objects/arrays to avoid mutating or freezing on complex types (like `Date`, `Error`, `Buffer`, or `RegExp`).
